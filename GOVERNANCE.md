# Governance and responsibilities

The project is maintained by the `4alvit` GitHub account. The primary maintainer
sets scope, reviews contributions, coordinates security reports and decides when
a tested change can be released. Contributors propose changes through public
issues and pull requests; significant compatibility or security decisions should
record their rationale there, except confidential vulnerability details.

Changes require the repository's normal checks and review. Automation may run
tests, create release candidates and record an opted-in approval; it does not
replace security judgment, physical acceptance or a responsible maintainer.
The release instructions define acceptance and publishing steps.

## Continuity

There is currently one primary maintainer. No backup person or tested mechanism
is in place to restore repository, CI and release access within one week if
that maintainer becomes unavailable. Public Git history and bots are not such
a mechanism. A future continuity plan requires an agreed responsible person,
appropriate access and a tested recovery exercise before this can be claimed.

## Community

Follow [the Code of Conduct](CODE_OF_CONDUCT.md),
[contribution instructions](CONTRIBUTING.md) and [security policy](SECURITY.md).
Conflicts and proposals can be discussed in issues; sensitive conduct reports
use the private contact in the Code of Conduct.
